# 公文排版规则

## 输入

- 支持 `.docx`、`.txt` 和直接传入的纯文本。
- 导入 `.docx` 时只读取段落文本，不保留原文复杂格式。
- 空行会被清理；导出时由规则重新插入必要空行。

## 段落识别

- 第一段非空文本识别为文档标题。
- 以 `一、二、三、四、五、六、七、八、九、十` 等中文数字加顿号开头的段落识别为一级标题。
- 以 `（一）（二）（三）` 等中文括号序号开头的段落识别为二级标题。
- 其他段落识别为正文。

## 默认版式

- 页面为 A4，210 mm x 297 mm。
- 页边距为上 36 mm、下 36 mm、左 27 mm、右 27 mm。
- 固定行距为 30 pt。
- 文档标题居中。
- 文档标题后插入一个空白段落，空白段落无文字，使用正文格式。
- 正文两端对齐，首行缩进 2 字符。
- 一级标题、二级标题按对应字号计算首行缩进 2 字符。

## 默认字体

- 文档标题：按关键字 `方正小标宋` 搜索本机字体，字号 `二号`。
- 一级标题：`黑体`，字号 `小二`。
- 二级标题：`楷体_GB2312`，字号 `小二`。
- 正文：`仿宋_GB2312`，字号 `小二`。
- 重点字段：`仿宋_GB2312`，字号 `小二`，加粗。

字体文件不随 skill 打包。脚本只检查字体名称并把最终字体名写入 `.docx`。

## 标题字体匹配

标题默认字体不是强制的单一字体文件，而是 `方正小标宋` 字体意图。

搜索用户电脑字体时，包含以下形式都可作为候选：

- `方正小标宋`
- `方正小标宋_GBK`
- `方正小标宋 GBK`
- `方正小标宋简体`

候选排序原则：

1. 规范化后与关键字完全相同。
2. 规范化后以关键字开头。
3. 名称中包含关键字。
4. 名称更短者优先。

脚本应报告最终选择的字体。如果没有候选，继续使用 `方正小标宋` 字体名并提醒用户安装或指定替代字体。

## 重点字段

默认重点字段为：

```text
分析认为
一是
二是
三是
四是
五是
六是
七是
八是
九是
十是
```

用户可以临时替换或追加重点字段。匹配时先匹配更长字段，避免短字段抢先匹配长字段。

## 标点规则

- 中文语境使用中文标点。
- 英文语境使用英文标点。
- 英文词位于中文句子中时，句末标点仍按中文语境处理。
- 例：中文句子里的 `"Codepilot".` 应输出为 `“Codepilot”。`
- 英文撇号位于英文单词内部时保留英文撇号，例如 `don't`。
- 数字小数点和简短数字序号里的点保留英文句点，例如 `3.14` 或 `1. 第一项`。
